# Mobile fullscreen, back and Kakao — 2026-10-13

Based on main f8ab0f5. User requested immersive mobile play, in-game back/exit confirmation, Kakao support, and reference to their SoriON/mastering projects. Inspected public junl-im/foxbear-mastering-studio src/boot/kakao-external-browser.js (61906909e2cc6e24c64c509f16909f10013d7e92), src/ui/mobile-native-view.js and qa/BROWSER_BACK_QA_MATRIX_1.4.26.md. Reused the approach of gesture-only external launch, copy/manual fallback, bounded history guard and deterministic end screen; did not import the mastering app runtime. Local SoriON delivery was desktop source and not treated as verified mobile reference.

Mobile entry immediately requests document fullscreen with navigationUI hide within the original user gesture. Visible fullscreen/restore and exit controls reflect actual fullscreen state. Rejected/unsupported fullscreen never prevents entry. Fullscreen loss on mobile prompts exit when the game is armed; intentional restore does not. viewport-fit cover, safe-area offsets, visualViewport resize and a route-relative fullscreen/standalone manifest support browser and home-screen launching. Original SVG game icon authored here. No service worker or offline gameplay added; platform install availability is not guaranteed.

One same-document history guard is armed for coarse/mobile contexts. Back re-arms that slot and opens a native dialog styled as game UI, without unbounded history growth. Confirmation freezes simulation and stops movement/combat/auto-hunt. Stay resumes simulation but does not restart auto-hunt. Confirm waits for any in-flight save then directly awaits a fresh write. Save failure keeps the dialog/game present. Saving cannot be cancelled midway. Successful exit uses known prior history when a referrer exists; otherwise shows a deterministic saved/ended screen with reopen. A normal page cannot guarantee closing the browser tab. Fullscreen/OS Back may first leave fullscreen; the fullscreenchange fallback covers that observable event, but browser UI and OS navigation interception remain platform-controlled. Refresh, process kill and Kakao's native close are not guaranteed to emit popstate.

Kakao detection supplies Android intent and iOS Kakao scheme buttons, only on user click. No timer or automatic scheme redirect. Clipboard failure displays a selectable URL field. Entry and in-game save/settings expose help. Browser-specific IndexedDB stores are separate: export/import or manual cloud save is needed to move progress. No credentials or saves are put into URLs.

Failure injection exposed an existing synchronous IDB put error escaping its request callback. writeSave now aborts the entire transaction and rejects the save promise for these errors, preserving both current and backup. Corrupt-current backup preservation remains covered.

Validation: typecheck/build and 99 local tests passed (single worker). Chromium native fullscreen/restore passed. Android-like Chrome and Kakao UA emulation: rejected-fullscreen entry, 3 back/cancel cycles with constant history length, paused simulation, injected IDB write failure blocks exit, retry succeeds and gold43 restores after reopen. These checks do not certify physical Android system-bar hiding, real Kakao intent launch or iOS home-screen installation.
