# 저장·장비 상세·자동이동·던전 진행

## 실제 문제와 수정

기존 save()는 쓰기 진행 중이면 같은 promise만 반환해 후속 스냅샷 요청을 버렸다. 실제 브라우저에서 IndexedDB open 성공 전달을 보류한 채 UI로 무기 해제→재장착 후 응답을 열면 화면은장착(true)인데 재접속은해제(false)로 복원됨을 확인했다. 고정600ms 지연만으로는 조작과 쓰기가 항상 겹치지 않아 재현되지 않았으므로, 실제 pending open을 관측하고 해제하는 순서로 재현했다. UI/플레이어/HP/퀘스트/처치/저장값은 강제하지 않았다.

latest-save-queue는 진행 중 쓰기 뒤 최신 요청 스냅샷1개를 직렬 저장한다. 모든 대기 호출은 마지막 쓰기까지 기다리고 실패하면 함께 reject한다. 다음 요청으로 재시도 가능하며 기존 IndexedDB 현재/백업 슬롯과 검증 규칙 유지.

방어구 슬롯은 상세·착용 여부·방어력 변화 확인용으로 선택하고, 명시적 착용/해제 버튼으로 변경한다. 기존 제작행의 빠른 착용/해제 유지. 장비/소모품 필터 전환 시 상세 선택을 맞춘다.

의뢰 자동이동은 A버튼에 이동/aria-pressed=true로 표시, 누르면 중단. 기존 ON/OFF·길게누르기 설정 유지.

던전 진행창은 실제 처치 수·다음 행동·버튼 가능 상태를 갱신한다. 현재 구역 자동사냥 버튼은 명시적 요청으로 nearest 기준 사냥을 시작한다. 구역 완료 후 중단하고 다음 구역/보상은 사용자가 선택한다. 물약 설정과 저체력 중단·마나·쿨다운·비용·보상 규칙 유지.

## 검증

실제 IndexedDB 첫/최신상태·이전백업·스냅샷 불변·실패 동시reject/재시도·동기예외 회귀4개, 원래 몬스터 배치 전투로 던전1구역 완료/중단·자동보상없음2개 추가. 기존 인벤 검사에 클릭만으로 장착 안 됨·상세 비교·명시적 착용 단정 추가.

별도 CI priority36-proof는 기존 PR22 원래 검사와 정상3의뢰(8처치)를 유지한 뒤 지연 IndexedDB·실제재료소비제작·장비선택/착용·3구역 정상사냥·보스보상+120G·재접속복원을 PC/모바일에서 검사한다. 기존 전체WebGL 작업은 그대로 유지하고 추가job으로 분리해35분 기존제한을 늘리지 않는다. 실제원래배치/정상전투이며 몬스터HP/플레이어좌표/의뢰값 강제 없음. 테스트 전용 IDB 성공응답 보류만 사용한다.

최종 CI/게시/백업 상태는 Notion MASTER와 PR 기록을 따른다.
